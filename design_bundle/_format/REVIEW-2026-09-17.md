# Review of export `new2` (2026-09-12 / 09-16)

Scope: `ds/export/components`, `ds/export/foundations`, `ui/export/screens`, `ui/export/assets`.
Where a component exists in both `ds/` and `ui/`, the `ds/` version was used.

Verdict: the export is sufficient to build both screens. 14 of 21 components need no
change. The items below are what blocks or distorts the build, then consistency fixes.

Severity: **[required]** affects what we build · **[recommended]** fact exists only in
prose · **[cosmetic]** form only.

---

## Screens — `ui/export/screens/`

**1. [required] Promo tiles have no geometry.** `Home.json`, section `custom-promo-tiles`:
only image paths. Missing: tile width, corner radius, shadow. Aspect ratio is derivable from
the files (512×264); the rest is not. Write it as a node:
`{ "type": "image", "size": [<width>, "auto"], "radius": "--radius-…", "shadow": "--elevation-…" }`.

**2. [recommended] Side margins are not stated.** Neither screen declares its horizontal
margin. We infer `--layout-margin` (16px). State it once at screen level.

**3. [recommended] Bottom navigation: sticky flag and chrome.** `Order.json` marks the
cart bar `"sticky": "bottom"`; `BottomNavigation` carries no such flag in either screen.
Its surface (background, top hairline) is not described. Obvious from context, but say it.

**4. [cosmetic] Prose inside fields.** `Order.json`:
- `"icon": "plus/x toggle"` — a field holds one icon name; the default state must be stated, the other goes in `variants`.
- `"variant": "filled/tonal toggle"` — same.
- `"background": "var(--glass-bg) with var(--glass-border), backdrop-filter blur(…)"` — three properties in one string; use `surface: { background, border }` as in components.

**5. [cosmetic] Spacing keys are named ad hoc.** The same concept gets a new name per
file: `spacingAfterTitle` and `titleSpacingAfter` are the same thing; `sectionSpacingAfter`
is `spacingAfter` one level down; `spacingAround` / `innerPadding` are `padding` on the
section and `surface.padding` on the inner box. Use a fixed set:

| Key | Meaning |
|---|---|
| `spacingAfter` | distance to the next section |
| `titleGap` | distance between a section's title and its content |
| `gap` | distance between items inside a section |
| `padding` | distance from the section edge to its content |

Anything nested inside a section uses the component node model (`surface.padding`, etc.).

## Assets — `ui/export/assets/`

**6. [required] `qr-code.svg` is missing.** `LoyaltyPointsCard.json` references
`./qr-code.svg`; the file is not in the export.

**7. [required] Eight products ship in two versions.** Each of these exists as `ch_*.png`
(600×600, referenced by the screens) and as `<name>-<hash>.png` (500×500, referenced by
nothing): bumble cherry, chocolate muffin, dubai cheesecake, hot salted caramel matcha,
ice americano, ice creamed cheese, iced fantasy coffee, raf strawberry. Which is canonical?
If the 500×500 set is newer, the screens point at the old files.

**8. [cosmetic] Eleven filenames contain spaces.** We will rename on import; a
space-free convention on export would avoid it.

## Components

### Required

**9. `BottomNavigation.json`** — root height is the number `64`, `showLabels: false`
sets `56`, and `notes` asserts "(64px)". `sizing.css` in this same export defines
`--bottomnav-height-labeled: 48px` and `--bottomnav-height: 48px`. Remove the numbers;
reference the tokens only.

**10. `LoyaltyPointsCard.json`** — (a) `qr` node references a missing file (item 6);
(b) `left.spacing` is `[0, 0]` while `notes` says the tier pill has `--space-xs` above it.
Put `--space-xs` in `spacing`.

**11. `TabBar.json`** — the active look of the `small` size (background `--gray-0`, border
`--color-brand-primary`, label `--color-text-accent`) exists only in `notes`. The `active`
variant case only changes label color to `--color-text-primary`, which is the `big` look.
Add the `small × active` case to `variants`.

**12. `Button.json`** — the default (primary, md) look has no `background` and no `radius`:
`surface` is `null`, the root row carries neither, and only `secondary` / `tertiary` /
`destructive` cases set a background. Add `surface: { background: "--button-primary-bg",
radius: … }`. Also: `Wallet.json` calls `Button` with `"radius": "full"`, but `Button` declares
no `radius` axis. Add it.

**13. `MembershipTierPill.json`** — `description` says "translucent pill on dark
surfaces"; the tree has no background at all. State the fill (`--alpha-white-8` / `-12` /
`-24`, whichever the design uses). Also `padding` is `12` / `4` as numbers; `--space-md` /
`--space-xs` exist.

### Recommended — fact is in `notes`, not in the tree

**14. `Stories.json`** — the 2px `--color-bg-surface` gap between the colored ring and the
photo is described in `notes` only. Model it as `border` on the `photo` node.

**15. `Dropdown.json`** — the open menu (surface, radius, shadow, option rows, selected
row) is described in `notes` only. Add a `menu` node, hidden by default, shown by the
`open` variant.

**16. Font weight in `notes`** — eight files say "weight is bold/semibold over
`--text-…`". Either the composite token already carries the weight (`--text-h1`, `--text-h3`
are bold per `foundations/typography-scale.json`, so the note is redundant) or the needed
token does not exist in CSS (`--text-body-sm-semibold` is in foundations only). Resolve by
adding the missing `--text-*` tokens to CSS and referencing them in `style`; drop the notes.

### Cosmetic

**17.** `"transparent"` as a background literal — `Greeting`, `IconButton`, `ScreenHeader`,
`TabBar`, `Wallet`. Use `null`.

**18.** `spacing` length ≠ children − 1 in `BranchCard` (root and hours row), `Dropdown`,
`Greeting`, `MenuTabsVertical`, `ProductMenuCard`, `ScreenHeader`, `TabBar`, `Wallet`.
Two notations for zero appear: `[0, 0]` and `[]`. Pick one.

**19.** `padding` written as a string (`"--space-xs"`) instead of an object —
`MenuTabsVertical`, `ProductMenuCard`, `TabBar`.

**20.** Fields outside the format: `overlayImage` (`LoyaltyPointsCard`), `weight` on text
nodes (`MenuTabsVertical`, `TabBar`), `rotate` (`Dropdown`), `margin` (`Divider`), `opacity`
(`Dropdown`, `IconButton`), `scale` (`BranchCard`); computed sizes `{1/n}`, `{size+8}`,
`{width}`; relative path `./qr-code.svg`. Each of these is a real need — `opacity` for
disabled, `rotate` for the caret — so we will add them to FORMAT.md rather than ask for
their removal. Until then, note them as extensions.

**21.** `shows.children` in `BranchCard`, `Wallet` — `children` is a React prop name; use
the slot's content name (`label`).

**22.** `Badge.json` — `name` is `"Badge (count)"`; names are identifiers, no parentheses.
`padding.x: 5` is off-scale and noted; fine.

## Cross-cutting

**23. [required] One component set.** `ds/export/components` (18) and
`ui/export/components` (19) overlap on 15 names with different content; `Button`,
`StatusPill`, `MembershipTierPill` exist only in `ui/`, while `ds/` components (`BranchCard`,
`Wallet`, `LoyaltyPointsCard`) compose them. Ship one folder, one generation, one
`version` date. Currently `ds/` mixes `2026-09-11`, `09-12`, `09-16`.

**24. [required] Foundations and CSS disagree.** `foundations/` defines six tokens that
are not in `tokens/*.css`: `--glass-bg`, `--glass-border`, `--glass-blur`,
`--button-height-xxs`, `--button-height-2xs`, `--text-body-sm-semibold`. `Order.json`
already uses the glass tokens. Add them to CSS, or remove them from foundations.

**25. [recommended] Foundations cover 183 of 262 tokens.** Missing: status color ramps
(green / amber / red / blue), alpha overlays, Tier-3 component aliases (`--button-*`,
`--input-*`, `--chip-*`, `--card-*`, …), shadows, transitions. If foundations is meant as the
token reference, it is incomplete; if it is a curated subset, say so in its README.

**26. [cosmetic] `_ds_manifest.json` lists token names only**, no values or kinds. Values
are in CSS and in foundations, so nothing is lost — but the manifest no longer serves as a
single machine-readable source.
