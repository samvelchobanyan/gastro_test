## Экраны — `ui/export/screens/`

**1. [обязательно] У промо-карточек нет геометрии.**
В `Home.json` секция `custom-promo-tiles` содержит только пути к картинкам. Не указаны:
ширина карточки, радиус скругления, тень. Пропорцию можно вывести из самих файлов
(512×264), остальное — нет. Без этого не знаем, какого размера рисовать карточку и есть ли
у неё скругление и тень. Записать как узел:
`{ "type": "image", "size": [<ширина>, "auto"], "radius": "--radius-…", "shadow": "--elevation-…" }`.

**2. [желательно] Боковые поля экрана не указаны.**
Ни один экран не говорит, какой отступ от края экрана до контента. Мы берём токен
`--layout-margin` (16px), но это наша догадка. Указать один раз на уровне экрана.

**3. [желательно] Нижняя панель: закреплённость и обвязка.**
В `Order.json` у cart-bar стоит `"sticky": "bottom"`, а у `BottomNavigation` такого флага
нет ни на одном экране. Не описана и её подложка — фон и линия сверху. По смыслу понятно,
но лучше сказать явно.

**4. [косметика] Проза внутри полей.**
В `Order.json` есть поля, где должно быть одно значение, а стоит фраза:
- `"icon": "plus/x toggle"` — в поле должно быть одно имя иконки. Нужно указать, какая по
  умолчанию, а вторую описать в `variants`.
- `"variant": "filled/tonal toggle"` — то же самое.
- `"background": "var(--glass-bg) with var(--glass-border), backdrop-filter blur(…)"` —
  три свойства одной строкой. Записать как `surface: { background, border }`, как у
  компонентов.
На вид не влияет, но читается только глазами и с догадкой.

**5. [косметика] Ключи отступов названы на ходу.**
Одно и то же понятие в разных файлах называется по-разному: `spacingAfterTitle` и
`titleSpacingAfter` — одно и то же; `sectionSpacingAfter` — тот же `spacingAfter`, только
уровнем ниже; `spacingAround` и `innerPadding` — это `padding` секции и `surface.padding`
вложенного бокса. Предлагаем фиксированный набор:

| Ключ | Значение |
|---|---|
| `spacingAfter` | расстояние до следующей секции |
| `titleGap` | расстояние между заголовком секции и её содержимым |
| `gap` | расстояние между элементами внутри секции |
| `padding` | расстояние от края секции до её содержимого |

Всё вложенное внутри секции — по модели узлов из формата компонентов.

## Компоненты

### Обязательно

**9. `BottomNavigation.json` — высота числом, и число не совпадает с токеном.**
В файле высота корня — число `64`, вариант `showLabels: false` ставит `56`, а в `notes`
написано «(64px)». При этом в `sizing.css` из этой же выгрузки оба токена
`--bottomnav-height*` равны `48px`. Внутри одной выгрузки два разных ответа. Убрать числа,
оставить только ссылку на токен.

**10. `LoyaltyPointsCard.json` — два пункта.**
(а) Узел `qr` ссылается на отсутствующий файл (см. п. 6).
(б) У колонки `left` записано `spacing: [0, 0]`, а в `notes` сказано, что над плашкой
уровня есть отступ `--space-xs`. Дерево и проза противоречат друг другу. Положить
`--space-xs` в `spacing`.

**11. `TabBar.json` — активный вид маленького таба только в прозе.**
Как выглядит активный маленький таб (фон `--gray-0`, рамка `--color-brand-primary`,
текст `--color-text-accent`), написано только в `notes`. В `variants` случай `active` меняет
лишь цвет текста на `--color-text-primary` — а это вид большого таба. Добавить в `variants`
случай `small × active`.

**12. `Button.json` — у кнопки по умолчанию нет ни фона, ни радиуса.**
Вид по умолчанию (primary, размер md): `surface: null`, на корне ни `background`, ни
`radius`. Фон появляется только в вариантах `secondary` / `tertiary` / `destructive`. Про
primary — нигде. Добавить `surface: { background: "--button-primary-bg", radius: … }`.
Второе: `Wallet.json` вызывает `Button` с `"radius": "full"` (капсула), но у `Button` оси
`radius` в вариантах нет. Один компонент заказывает вид, который другой не описывает.
Добавить ось.

**13. `MembershipTierPill.json` — нет заливки.**
В `description` сказано «полупрозрачная плашка на тёмных поверхностях», а в дереве фона нет
совсем. Указать заливку (`--alpha-white-8` / `-12` / `-24` — какая по дизайну). Ещё:
`padding` записан числами `12` / `4`, хотя есть токены `--space-md` / `--space-xs`.

### Желательно — факт есть, но только в `notes`, не в дереве

**14. `Stories.json` — белый зазор только в прозе.**
Между цветным кольцом и фото есть зазор 2px цвета `--color-bg-surface`. Об этом сказано
только в `notes`. Записать как `border` на узле `photo`.

**15. `Dropdown.json` — раскрытое меню только в прозе.**
Как выглядит открытый список (подложка, радиус, тень, строки, выбранная строка) —
описано только в `notes`. Добавить узел `menu`, скрытый по умолчанию и показываемый
вариантом `open`.

**16. Вес шрифта в `notes` у восьми файлов.**
Восемь компонентов пишут в `notes` «вес bold/semibold поверх `--text-…`». Либо токен уже
несёт этот вес (`--text-h1`, `--text-h3` в `foundations/typography-scale.json` уже bold —
тогда заметка лишняя), либо нужного токена нет в CSS (`--text-body-sm-semibold` есть только
в foundations). Решение: добавить недостающие `--text-*` в CSS, ссылаться на них в `style`,
заметки убрать.

### Косметика

**17. `"transparent"` как значение фона.**
В `Greeting`, `IconButton`, `ScreenHeader`, `TabBar`, `Wallet` поле `background` содержит
слово `"transparent"`. По формату значение — либо токен, либо число, либо слово из
закрытого списка; `"transparent"` — слово из CSS, его в списке нет. «Без заливки» в формате
записывается как `null`. Заменить.

**18. Длина `spacing` не равна `детей − 1`.**
По формату у контейнера ровно на одно расстояние меньше, чем детей. Нарушено в
`BranchCard` (корень и строка часов), `Dropdown`, `Greeting`, `MenuTabsVertical`,
`ProductMenuCard`, `ScreenHeader`, `TabBar`, `Wallet`. Кроме того, ноль записывают двумя
способами: `[0, 0]` и `[]`. Выбрать один.

**19. `padding` строкой вместо объекта.**
В `MenuTabsVertical`, `ProductMenuCard`, `TabBar` написано `"padding": "--space-xs"`, а по
формату это объект `{ "all": "--space-xs" }` или по сторонам.

**20. Поля, которых нет в формате.**
`overlayImage` (`LoyaltyPointsCard`), `weight` на текстовом узле (`MenuTabsVertical`,
`TabBar`), `rotate` (`Dropdown`), `margin` (`Divider`), `opacity` (`Dropdown`, `IconButton`),
`scale` (`BranchCard`); вычисляемые размеры `{1/n}`, `{size+8}`, `{width}`; относительный
путь `./qr-code.svg`. Каждое из них — реальная потребность (`opacity` для disabled, `rotate`
для стрелки), поэтому мы добавим их в `FORMAT.md`, а не будем просить убрать. Пока —
считать расширениями.

**21. `shows.children` в `BranchCard`, `Wallet`.**
`children` — имя пропса из React. Использовать имя слота с содержимым (`label`).

**22. `Badge.json` — имя со скобками.**
`name` записан как `"Badge (count)"`. Имя — идентификатор, скобок быть не должно.
`padding.x: 5` вне шкалы, но это отмечено в `notes` — допустимо.

## Сквозное

**23. [обязательно] Один набор компонентов.**
`ds/export/components` (18 файлов) и `ui/export/components` (19) пересекаются по 15
именам, и содержимое разное. `Button`, `StatusPill`, `MembershipTierPill` есть только в
`ui/`, при этом компоненты из `ds/` (`BranchCard`, `Wallet`, `LoyaltyPointsCard`) их
используют. Нужна одна папка, одна генерация, одна дата в `version`. Сейчас в `ds/`
смешаны `2026-09-11`, `09-12`, `09-16`.

**24. [обязательно] Foundations и CSS расходятся.**
В `foundations/` определены шесть токенов, которых нет в `tokens/*.css`: `--glass-bg`,
`--glass-border`, `--glass-blur`, `--button-height-xxs`, `--button-height-2xs`,
`--text-body-sm-semibold`. `Order.json` уже использует glass-токены. Либо добавить их в CSS,
либо убрать из foundations.

**25. [желательно] Foundations покрывают 183 токена из 262.**
Нет: статусных рамп (green / amber / red / blue), alpha-оверлеев, компонентных алиасов
Tier-3 (`--button-*`, `--input-*`, `--chip-*`, `--card-*` …), теней, переходов. Если
foundations задуман как справочник по токенам — он неполный; если это выборка — сказать об
этом в README.

**26. [косметика] `_ds_manifest.json` содержит только имена токенов**, без значений и типов.
Ничего не потеряно — значения есть в CSS и в foundations — но манифест больше не годится
как единый машиночитаемый источник.
